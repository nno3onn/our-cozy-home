# 우리집 결정 기록

최종 수정일: 2026-09-19

제품 명세가 정하지 않은 되돌리기 쉬운 기본값과 선택 이유를 기록한다. 제품 규칙을
바꾸는 결정은 이 문서만 수정하지 않고 `product-spec.md`도 함께 갱신한다.

## D-001 저장소와 패키지 관리

- 상태: 채택
- 결정: 단일 Expo 앱과 `supabase` 디렉터리를 한 저장소에 둔다. 패키지 관리자는
  npm을 사용하고 잠금 파일을 커밋한다.
- 이유: 첫 버전에 별도 서버가 없고 Expo 기본 도구와 가장 단순하게 호환된다.

## D-002 실행 모드 선택

- 상태: 채택
- 결정: `EXPO_PUBLIC_APP_MODE=demo|supabase`를 명시적으로 선택한다. 값 또는 실제
  모드 환경 변수가 잘못되면 설정 오류를 보여주고 자동으로 데모로 전환하지 않는다.
- 이유: 목업 동작을 실제 연동 성공으로 오인하지 않게 한다.

## D-003 데모 상태 저장

- 상태: 채택
- 결정: 첫 구현은 메모리 기반 데모 repository를 사용하고 데모 전용 초기화 명령을
  제공한다. 앱 재시작 뒤 영구 보존은 보장하지 않는다.
- 이유: 인증 정보 없이 모든 핵심 화면을 재현하면서 실제 데이터 계층과 분리한다.

## D-004 방 좌표와 배치

- 상태: 채택
- 결정: `1000 x 1000` 논리 좌표와 카테고리별 고정 슬롯을 사용한다. 드래그는
  자유 좌표가 아니라 가장 가까운 호환 슬롯을 선택한다.
- 이유: 화면 크기 차이를 흡수하고 첫 버전의 충돌·동기화 복잡도를 제한한다.

## D-005 추억 글 수정 이력

- 상태: 채택
- 결정: 기여 글은 revision을 추가하며 viewer의 퇴장 시각 이전 마지막 revision을
  조회한다. 원본 삭제는 revision 시점과 무관하게 모든 접근을 차단한다.
- 이유: 탈퇴 당시 공개 범위를 유지하면서 원작자 삭제 정책을 일관되게 적용한다.

## D-006 계정 삭제와 공동 추억

- 상태: 채택
- 결정: 계정 삭제 시 본인의 공동 기여 글·사진은 삭제하고 작성자 정보를
  비식별화한다. 다른 사용자의 기여와 이미 확정된 추억 가구는 유지한다.
- 이유: 본인 콘텐츠 정리 요청과 공동 결과의 타 사용자 소유권을 함께 보존한다.

## D-007 사진 업로드 제한

- 상태: 채택
- 결정: JPEG, PNG, HEIC/HEIF 원본 10MB 이하만 받고 긴 변 2048px, JPEG 품질
  0.82로 압축한다. 결과가 5MB를 넘으면 업로드하지 않는다.
- 이유: 모바일 품질을 유지하면서 Storage와 전송 비용을 제한한다.

## D-008 에셋 완성 상태

- 상태: 채택
- 결정: 카탈로그에 `placeholder|final` 상태를 둔다. 동물 두 종과 가구 한 테마로
  방 스타일을 먼저 검증하고 나머지 항목은 그 전까지 placeholder로 표시한다.
- 이유: 55개 외형의 양보다 시점·비율·윤곽선의 일관성을 먼저 확정한다.

## D-009 불확실한 구매 응답

- 상태: 채택
- 결정: 구매 응답이 끊기면 같은 멱등 키의 결과 조회 RPC로 조정한 후 결과가 없을
  때만 같은 키로 재시도한다.
- 이유: 네트워크 실패와 서버 처리 실패를 구분해 이중 차감·지급을 막는다.

## D-010 구현 단위

- 상태: 채택
- 결정: 화면 전체, 서버 전체 순서가 아니라 집, 경제, 추억처럼 기능별로 화면,
  repository, RPC, RLS, 오류와 테스트를 연결해 완성한다.
- 이유: 각 단계가 실행 가능하며 실제 사용자 흐름의 누락을 조기에 발견할 수 있다.

## D-011 실제 계정 삭제 실행자

- 상태: 채택
- 결정: 앱 데이터 정리는 멱등한 삭제 요청으로 기록하고 Supabase Auth 사용자 삭제는
  service role을 가진 Edge Function이 마지막에 수행한다.
- 이유: service role key를 앱에 포함하지 않고 부분 실패를 안전하게 재시도한다.

## D-012 파일럿 방의 시각 구조

- 상태: 채택
- 색상: 종이 크림 `#FFF8E8`, 바닥 모래 `#F0DFC0`, 먹색 `#38332E`, 복숭아
  `#F2A98C`, 민트 `#91C9AF`, 하늘 `#94BFE0`을 사용한다.
- 글꼴: 작은 화면의 한국어 가독성과 네이티브 일관성을 위해 플랫폼 산세리프를
  사용하고 크기·굵기·행간으로 위계를 만든다.
- 배치: 방을 종이 인형극 무대처럼 화면의 대부분에 두고, 정보는 상단의 얇은
  집 이름·인원 띠와 하단의 하나뿐인 행동 패널에 모은다.

```text
┌ 우리집 이름                         4/4 ┐
│                                            │
│            벽과 창, 교체 가구             │
│       동물+이름표       동물+이름표        │
│          러그와 탁자, 식물                 │
│       동물+이름표       동물+이름표        │
├ 선택한 동물 상태와 먹기·쉬기·놀기 버튼 ───┤
└ 우리집          꾸미기          추억       ┘
```

- 원칙: 기억에 남는 요소는 동일한 둥근 카드 묶음이 아니라 네 동물이 함께 있는
  방 무대다. 이름표는 사용자 색의 작은 천 라벨처럼 보이되 색만으로 구분하지 않는다.
  그림자는 모두 오른쪽 아래 한 방향이고 패널은 동물의 얼굴과 주요 가구를 가리지
  않는다.
- 검토: 크림+테라코타 중심의 흔한 랜딩 페이지 인상을 피하려고 갈색 대비를 줄이고
  민트·하늘색을 주요 상호작용 색으로 옮겼다. 불필요한 그라데이션, 다수의 둥근 카드,
  장식용 영문 라벨과 자동 등장 애니메이션은 사용하지 않는다.
