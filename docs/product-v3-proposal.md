# 우리집 제품 v3 제안 — 친구와 함께한 시간이 눈에 보이는 집

작성: 2026-10-17 · 상태: **개발 방향·수용 기준 제안, 운영 정책 변경 승인 아님**

이 문서는 사용자가 이번 요청에서 지정한 v3 방향을 저장소의 개발 판단 기준으로 옮긴다.
[현행 운영 계약](product-spec.md)은 유지하며, 자산·경제·학습·공용 소유권 변경은
[승인 대기 결정](product-v3-decisions-needed.md)을 통과하기 전 구현·적용하지 않는다.
실제 구현 위치와 검증 이력은 [로드맵](product-v3-implementation-roadmap.md)에 분리한다.
문서 병합·기능 PR 병합·운영 DB 적용·배포·실제 사용자 검증은 각각 다른 상태다.

## 다음 세션이 먼저 이해할 것

1. 방에 들어와 동물과 즉시 교감하고, 친구와 작은 공간 변화를 만든다.
2. 함께 겪은 순간을 각자의 말로 기록하면 같은 가구가 남는다.
3. 다시 방문하면 친구가 남긴 변화를 발견한다. 접속하지 않았다는 벌·연속 출석 압박은 만들지 않는다.
4. C01·C03의 권한·영속성·동기화가 안전해야 이 경험을 신뢰할 수 있다.
   하지만 기술 기반만 늘리지 않고 C02 → C04/C05 → C08 → C06 → C07을 완결한다.
5. 현행 개인 자산은 그대로 둔다. 무료 체험의 필요성은 개인 가구를 공용으로 바꾸는 승인이 아니다.

## 공통 경험·보안·측정 계약

- 320px·1280px에서 같은 장면 좌표와 저장 결과를 사용한다. 방·주요 행동은 가리지 않고,
  보관함 등 보조 내용은 필요하면 내부 스크롤/시트로 읽는다. 큰 글자 접근성을 위해
  ‘모든 높이에서 절대 스크롤 금지’를 강제해 조작을 자르지 않는다.
- 터치는 최소 44pt, 이름+‘내 동물’ 등 텍스트로 소유자를 표시하고 색만으로 구별하지 않는다.
  가구·동물 hit area와 레이어를 함께 검증한다. 모션 감소 시 정적 최종 표정과 안내를 제공한다.
- 로컬의 일시적 표정·미리보기와 서버의 영속 상태·자산 확정을 구분한다. 연출 종료로 지급하지 않는다.
- transport 오류와 권한 거부를 구분한다. 오프라인에는 같은 계정의 마지막 승인된 캐시를
  읽기 전용으로 유지하되, 로그아웃·퇴장·확정 권한 상실 뒤에는 다시 표시하지 않는다.
- viewer grant·Storage·원본 삭제·퇴장 cutoff는 유지한다. 목록 수·제목·이벤트 ID·빈자리로도
  비공개 사건의 존재를 추론할 수 없게 한다. 딥 링크와 알림도 현재 권한을 재검사한다.
- 성공 선언에는 화면/Repository/RPC/RLS/DB/재접속/실제 사용자를 각각 적는다.
  아래 수용 기준은 앞으로 확인할 기준이며 이번 문서 PR의 통과 결과가 아니다.

## C01. 최대 4명이 함께 사는 집

### 존재 이유

친구와 만든 장면을 같은 주소와 맥락에 보존하는 기반이다. 채팅방·연락처처럼 관계만 나열하지 않고 함께 남긴 결과를 공유한다.

### 사용자 문제

집을 만들고 초대해도 누구와 사는지, 빈자리가 있는지, 나가면 무엇이 남는지 알기 어렵다.

### 함께/혼자 가치

함께: 최대 네 동물과 서로의 변화가 같은 방에 보인다. 혼자: 빈자리 압박 없이 자기 동물과 개인 기록·보유 가구로 시작하고 초대는 선택한다.

### 사용자 흐름

로그인·온보딩 → 집 선택에서 만들기 또는 초대 확인 → 집 이름/초대 최소 정보 확인 → 서버 확정 → 1/4와 빈자리 → B 초대·입주 후 2/4 → 집 나가기 영향 확인 → RPC 성공 직후 집 선택. 집장 퇴장 시 선가입자 승계, 마지막 퇴장만 archive. 재입주는 새 membership이며 과거 grant를 복원하지 않는다. 온보딩 화면 순서는 기존 로컬 요청·서버 선행조건을 별도 정합화하고 이 문서로 서버 순서를 바꾸지 않는다.

### 즉각 피드백

입주 확정 후 이름·내 동물 표시·인원 갱신. 초대 미리보기는 자리 예약이 아니다. 퇴장 성공은 옛 방을 즉시 가리고 안전 화면으로 이동한다.

### 재방문 이유

친구가 내 자리를 포함한 방에 남긴 변화를 확인한다. 출석 횟수나 빈자리의 불이익으로 방문을 강제하지 않는다.

### 단순 대안 비교

친구 목록은 초대에는 충분하지만 같은 장소·장식의 공동 결과를 주지 못한다. 공개 광장은 개인정보와 정원 복잡성이 커져 도입하지 않는다.

### 오프라인·실패·빈 상태

집 없음은 만들기/초대 선택, 만원·만료·취소는 원인 안내. 연결 실패는 집 없음으로 판정하지 않는다. 오프라인 입주/퇴장 금지, 확정 권한 거부 시 옛 캐시 숨김. pending과 확정된 0명/빈 방은 구분한다.

### 소유권·RLS·개인정보

한 계정 활성 집 하나·정원 4·admin 초대·24시간·승계·재입주 제한 유지. 초대에 추억/재고를 싣지 않는다. 퇴장 후 방 접근은 차단하되 본인의 허용된 참여 추억 보관함은 별도 cutoff로 유지한다.

### 데이터·서버 책임

profiles/animals/houses/house_memberships/house_invites/invite_acceptances/house_create_requests. 생성·초대·수락·leave RPC가 잠금·정원·멱등성·승계·회수를 원자적으로 확정. 클라이언트는 actor/house 세대별 캐시·구독을 분리한다.

### 의존성

기존 집 계약 재사용. 단계 0 #164/#167/#169/#172 통합 및 퇴장 UI·캐시 후속이 관련된다. #170은 증거 참고만 하고 병합하지 않는다.

### Demo/Supabase/Web/Native 검증

Demo의 미지원 create/join/leave를 실제 성공으로 꾸미지 않는다. 격리 Supabase에서 솔로→2인→4인/다섯째 거부, 동일 마지막 자리 경합, 승계·재입주를 SQL+실제 A/B UI로 확인한다. Web 320/1280, Native 실제 딥 링크·back·secure session은 별도다.

### 수용 기준

활성 membership 중복0, 정원 초과0. A 퇴장 성공 뒤 옛 방 픽셀/캐시가 나타나지 않고 B 화면의 A 가구가 승인된 수렴 시간 안에 제거된다. 탈퇴 JWT·직접 URL·옛 지연 요청이 새 집을 수정하지 못한다. 솔로도 동물까지 도달한다.

### 제거·축소 기준

초대 조작이 혼자 시작을 막으면 초대 노출을 축소한다. 집의 관계·권한 기반은 제거하지 않는다. 공개 매칭·강제 퇴장 등 가치가 증명되지 않은 확장은 보류한다.

## C02. 동물의 즉각적인 반응

### 존재 이유

접속 직후 손길에 반응하는 존재가 있어야 방이 살아 있다고 느낀다. 상태 텍스트나 보상 수령은 이 순간을 대체하지 못한다.

### 사용자 문제

PNG가 통째로 흔들리거나 눈이 튀고 귀·발이 잘리면 인형이 살아 움직이기보다 오류처럼 보인다. 내 동물 식별도 어렵다.

### 함께/혼자 가치

함께: 같은 종이라도 이름·주인·차분한 반응으로 구별한다. 혼자: 친구 접속을 기다리지 않고 세 가지 손길 반응 자체를 즐긴다.

### 사용자 흐름

홈 진입 → 내 동물 이름/표시 확인 → 몸을 터치 → 고개 인사·눈웃음 → 놀아주기 → 앞발 내밀기·작은 몸 자세 변화 → 쉬기 → 눈 감고 숨쉬기 → 기본 자세 복귀. 같은 버튼 연타는 큐를 무한히 쌓지 않는다. 친구 터치는 로컬 인사 표현이며 영속 상태 변경·C07 전달과 구별한다.

### 즉각 피드백

제안 목표: 터치 후 500ms 이내 첫 시각 변화, 3종 이상 식별 가능한 표정/자세. 발 기준점·개체 크기·귀/젤리 일관성 유지. 모션 감소에서는 정적 표정+접근성 안내. 성공 응답 전 영속 상태 저장 완료라고 표시하지 않는다.

## C03. 공동 방 꾸미기

### 존재 이유

친구와 함께한 시간이 같은 공간의 눈에 보이는 변화로 남아야 한다. 구매만 하고 방에 보이지 않으면 가구의 가치는 사라진다.

### 재방문 이유

친구가 놓은 장식과 내 배치가 이어져 집에 이야기가 쌓인다. 꾸미기 자체에 일일 횟수 숙제를 붙이지 않는다.

## C04. 두 명이 만드는 공동 추억

### 존재 이유

한 사람의 게시물에 반응하는 것을 넘어, 같은 순간의 서로 다른 기억이 함께 남아야 공동 경험이 된다.

### 사용자 문제

누구에게 공유되는지 모르거나 B가 기여할 입력 경로가 없으면 사진 게시판에 그친다. 긴 글·사진 의무는 기여 부담을 만든다.

### 함께/혼자 가치

함께: A와 B의 관점을 한 기록에서 비교한다. 혼자: 비공개 초안을 남기고 공유 여부를 나중에 선택한다. 친구가 생겼다는 이유로 자동 공유하지 않는다.

### 사용자 흐름

추억 탭 → 새 추억 → 제목·나의 한 줄(사진 선택) → 비공개 저장 → 현재 공유 대상 이름 확인 → 작성자가 명시 공유 → B가 허용된 목록/상세 진입 → ‘나는 그날 이렇게 기억해요’ 한 줄 입력 → 자기 기여 저장 → 두 사람 내용과 완료 결과 확인. A의 수정·여러 사진은 두 번째 사람으로 계산하지 않는다.

### 즉각 피드백

공유 전 ‘나만 볼 수 있어요’, 공유 확정 후 고정 대상, 기여 저장 후 본문·기여자 표시. 사진 실패는 ‘글 저장됨/사진 재시도’로 분리. 가짜 친구 기여·완료 seed를 실제 행위 결과로 보여주지 않는다.

### 재방문 이유

친구가 같은 순간을 어떻게 기억했는지 읽고 덧붙인다. 일일 기록 수·연속 작성·답변 강요는 없다.

### 단순 대안 비교

사진 앨범은 쉬우나 두 관점과 공동 결과를 약화한다. 댓글은 비교 대조 대상으로 쓰되 새 질문 게임이나 장문 설문을 추가하지 않는다. 한 줄로 가치가 생기는지 먼저 검증한다.

### 오프라인·실패·빈 상태

읽기는 승인 캐시 범위, 저장·공유·기여는 온라인에서 서버 확정. 입력은 실패 후 유지하되 계정 변경 때 다른 계정에 노출하지 않는다. 초안/사진 재시도 멱등성은 검증 후 연결. 솔로/추억0에는 개인 초안 CTA, 권한0에는 제목·카운트 없이 안전한 안내.

### 소유권·RLS·개인정보

작성자만 초안 조회·공유. 공유 시 membership snapshot 고정, 후입주/재입주 자동 grant 금지. B는 자기 기여만 수정. 퇴장 직접 기여자는 cutoff 보관함, 원본 삭제는 전 범위 반영. 초대/알림에 내용·존재를 싣지 않는다.

### 데이터·서버 책임

memories/memory_viewers/memory_contributions/revisions/photos와 비공개 Storage. create/share/add/revise/delete RPC가 author·viewer·활성 membership 검사. 한 줄은 공백만 제외한 본문으로 정의하고 서버 검사도 확인한다. 사진 압축·업로드·완료 확정을 글 저장과 구분한다.

### 의존성

#156/#161, 기존 SQL/RPC 및 로컬 MemoryContributionForm·draft recovery 우선 검증. C05 완성 사건과 연결하되 새 소셜 정책·push에 의존하지 않는다.

### Demo/Supabase/Web/Native 검증

## C05. 추억이 가구가 되는 경험

### 존재 이유

기록이 목록에만 묻히지 않고 집에 남아, 함께한 순간을 눈으로 다시 만나는 핵심 결과다.

### 사용자 문제

두 명이 글을 썼는데 완료 표시만 뜨거나 가구가 보이지 않으면 공동 기록의 보상이 추상적이다. 중복 지급은 공동 결과의 신뢰를 해친다.

### 함께/혼자 가치

함께: 둘의 기여가 같은 출처의 가구 하나로 보인다. 혼자: 작성자는 초안을 보관하며, 이미 권한 있는 추억 가구는 다시 읽고 꾸밀 수 있다. 혼자 두 사람 완성을 위조하지 않는다.

### 사용자 흐름

C04 B 기여 서버 성공 → 완료 상태/실제 가구 ID 재조회 → 가구·참여자·원본 추억과 소유자 A를 한 화면에 표시 → 소유자 A에게만 ‘방에 놓기/보관함에 두기’, B에게는 완성 보기·원본 열기 → A가 C03 미리보기/취소/확정 → 친구 화면·재접속에서 같은 가구 → 가구 터치 → 현재 viewer 권한으로 원본 열기. 무관한 일반 라디오는 추억 상세로 보내지 않는다.

### 즉각 피드백

실제 이번 완료 전환을 확인했을 때 한 번만 차분한 축하. 응답이 contribution ID뿐이면 재조회로 완성을 확인하고 임의로 owned item을 만들지 않는다. 이미 완료된 가구 재열람은 지급 축하를 반복하지 않는다.

### 재방문 이유

눈앞의 가구에서 그날 서로의 말을 다시 읽고 또 다른 순간을 남긴다. 매일 가구 획득 미션은 없다.

### 단순 대안 비교

완료 배지·코인은 한눈에 쉬우나 집에 남는 공동 의미가 약하다. 여러 랜덤 지급·희귀도 경쟁보다 정확한 출처와 원본 연결 하나를 우선한다.

### 오프라인·실패·빈 상태

응답 유실은 memory_id 기반 기존 완료 조회 후 복구하고 재지급하지 않는다. offline 확정 금지, 허용 캐시 가구는 보되 원본 signed URL 재발급은 온라인 확인. 권한 취소 시 가구/제목/연결을 숨긴다. 아직 한 명이면 대기 상태, 로딩이면 미완성으로 단정하지 않는다.

### 소유권·RLS·개인정보

현행 가구는 author의 owned_item, 공동 의미가 공용 소유권은 아니다. 두 번째 기여자 B에게 소유자 전용 배치 CTA를 활성화하지 않는다. 현재 멤버 중 원본 권한 없는 사람이 있으면 방 노출을 막는 명세 유지, 개인 허용 보관함과 분리. 모든 가구 터치/URL에서 viewer 재확인, 후입주·퇴장·원본 삭제 규칙 유지.

### 데이터·서버 책임

기존 complete_memory_if_ready, owned_items.memory_id 고유, memory_completion_events.memory_id 고유 및 row lock 재사용. distinct author 두 명(동일 author 수정 제외)에서 한 번 생성. 생성과 배치 분리, DB가 원본 ID·가구 ID 확정. 서버 응답 확대는 새 계약 PR로 한다.

### 의존성

C04와 단계 0 C03. #156의 완결 PR에서 기여→생성→보관함→배치→원본까지 연결. #154 전체 이동/undo나 무료 정책 확정까지 기다릴 필요 없음.

### Demo/Supabase/Web/Native 검증

Demo 같은 session의 두 관점 상태 전이를 명시적으로 모델링, 새로고침 영속성 주장은 안 함. 격리 Supabase 두 번째 기여 동시 실행/응답 유실 후 가구·event 정확히1, 재로그인 원본 열기, 후입주자/퇴장자/원본 삭제. Web 전 허용 슬롯 320/1280, Native 원본 모달·터치·모션 감소 별도.

### 수용 기준

## C06. 지난번 이후 친구가 남긴 변화

### 존재 이유

동시에 접속하지 못해도 친구가 이 집에서 시간을 보냈다는 흔적을 발견하게 한다.

### 사용자 문제

방에 무엇이 바뀌었는지 모르고, 일일 미션 카드만 보이면 재방문할 관계적 이유가 없다.

### 함께/혼자 가치

함께: 부재중 친구의 배치/추억 완성 최대3건을 발견. 혼자: 변화 없음을 자연스럽게 받아들이며 가짜 활동·초대 압박은 표시하지 않는다.

### 사용자 흐름

집 진입 → 서버가 현재 membership의 이전 방문 경계~이번 readAt 조회 → 본인 제외·권한 허용 사건만 최신3건 → ‘보리가 쿠션을 놓았어요’ 선택 → 현재 방 변화/허용 추억으로 이동 → 표시 성공 뒤 같은 membership/readAt 방문 기록. 새 경계 이후 사건은 다음 조회에 남긴다.

### 즉각 피드백

현재 배치 강조 또는 허용된 완료 가구로 연결. 과거 사건의 가구가 이미 회수됐으면 현재 상태 안내. 읽기 실패를 변화0건으로 표시하지 않고 재시도. 같은 사건 재조회에서 보상을 지급하지 않는다.

### 재방문 이유

내가 없을 때 친구가 바꾼 작은 흔적을 찾아보고 내 변화도 남긴다. ‘오늘’ 기준 초기화·연속 방문 보상은 쓰지 않는다.

### 단순 대안 비교

읽지 않은 알림 수는 시급함을 과장한다. 전체 활동 로그는 과하고 정보 노출 면적이 크다. 최신3건 요약과 방 직접 보기가 더 가치 있는지 비교한다.

### 오프라인·실패·빈 상태

offline에는 새 소식이라고 조작하지 않고 이미 허용된 요약에 기준 시각 표시, 방문 watermark 쓰기 금지. 실패 시 방문 경계를 진행시키지 않는다. 0건은 조용히 숨기거나 ‘지난번 이후 새 변화가 없어요’. 권한 거부 시 캐시 폐기.

### 소유권·RLS·개인정보

필터는 limit/count 전에 서버에서 적용. 비공개 추억의 제목·유형·존재·제외 건수도 미노출. 새 membership은 joinedAt 이전 사건 접근 불가. 재입주 watermark·옛 비동기 응답 재사용 금지. 게시 당시뿐 아니라 조회 시 현재 권한도 검사.

### 데이터·서버 책임

확정 배치/완료 사건 원장과 membership별 last-visit. 조회 결과에 readAt/경계 식별자, ack는 같은 membership·단조 증가·서버 시각 범위. list_house_news/mark_house_news_visited 로컬 계약을 검증해 채택할지 결정하며 새로운 수집 이벤트는 최소화한다.

### 의존성

단계 0 확정 배치 사건과 C05 실제 완료 사건. #157, 로컬 house-news 코드/SQL부터 재사용. 선행 추억 권한 없으면 일반 배치 소식만 제한적으로 검증하고 추억 소식 완료라 하지 않는다.

## C07. 친구 동물에게 조용한 인사

### 존재 이유

긴 글이나 실시간 약속 없이도 친구가 생각났다는 마음을 한 번의 작은 행동으로 남기게 한다.

### 사용자 문제

친구가 offline일 때 할 수 있는 행동이 없거나 친구 동물 상태를 바꾸는 것만 가능하면 의도와 권한이 어긋난다.

### 함께/혼자 가치

함께: 상대가 원할 때 확인할 작은 인사를 받는다. 혼자: 수신자 없는 버튼은 숨기고 기본 교감을 계속 제공한다. 봇 수신자·가짜 답장은 만들지 않는다.

### 사용자 흐름

친구 동물 선택 → ‘조용히 인사 남기기’ → 서버가 같은집·설정·제한·요청키 검사 → 발송 확정 후 작은 손인사 → 친구가 다음 접속에서 수신 확인 → 숨김/음소거/차단. 인사 UI는 상태 변경 버튼과 분리, 반복 클릭으로 여러 건을 보내지 않는다.

### 즉각 피드백

로컬 짧은 몸짓과 ‘인사를 남겼어요’는 서버 성공 뒤. 전송 중/이미 보냄/허용되지 않음을 부담 없는 안내로 구분한다. 실제 수신·읽음을 확인하지 않고 ‘친구가 봤어요’라 표시하지 않는다.

### 재방문 이유

내 동물을 찾은 친구의 따뜻한 흔적을 발견한다. 답례 의무·읽음 경쟁·인사 횟수 보상은 만들지 않는다.

### 단순 대안 비교

채팅·좋아요는 익숙하지만 내용/읽음 관리와 사회적 압박을 늘린다. 한 가지 인사를 먼저 검증하고 감정 메뉴·선물 경제·푸시는 붙이지 않는다.

### 오프라인·실패·빈 상태

offline 전송/자동 큐 금지. 응답 불명은 같은 request key로 결과 조정, 성공 오인 방지. 친구 없음은 숨김. 차단/권한 상실은 상대 상세를 노출하지 않는 중립 실패, 실패 후 friend state는 그대로.

### 소유권·RLS·개인정보

sender=auth.uid(), 현재 같은집 상대만, 자기 전송 금지. 수신자만 내역/설정 접근. 보내는 사람이 상대 영속 animal.state를 변경하지 않음. 퇴장/재입주에는 기존 내역의 membership 범위 재검사. 차단 여부를 구체적 사유로 발신자에게 노출하지 않음.

### 데이터·서버 책임

로컬 quiet-greeting 원장/수신설정/숨김·멱등 요청 SQL을 우선 감사. 제안 상한은 발신-수신 쌍 24시간1회와 계정 총량 상한의 조합(정확한 총량/보관기간 D07 승인 필요). 쓰기 시 원자적 제한, 재시도 키 검증; push 기본 추가 안 함.

### 의존성

C02 친구 로컬반응/본인서버변경 분리, 단계 0 세션/집 경계, #160. 로컬 service/components/migration 보존·추출; 설정/차단 누락 상태로 보내기만 출시하지 않는다.

### Demo/Supabase/Web/Native 검증

Demo 재시도·제한·숨김·차단 모델, Supabase A→B발송/B조회/A직접수정거부/다른 집·퇴장거부·동시반복 제한. Web320/1280 수신/설정 접근성, Native foreground/notification은 별도이고 push 미구현을 밝힌다.

### 수용 기준

한 의도 한 인사, 권한 없는 송수신/상대 상태변경0, 제한 내 원자적 전송. 음소거·차단·숨김 실제 동작, 로그아웃 후 다른 계정에 수신함 노출0. 2인 평가에서 응답 압박 발생 여부를 기록한다.

### 제거·축소 기준

답장 압박·스팸이나 가치 없는 탭 반복이 관찰되면 발송 빈도/표현을 줄이고 도입 보류. 수신 제어 없이 확대하지 않는다. 기존 원장 삭제는 승인된 보관 정책으로만 한다.

## C08. 가구와 동물의 상황별 상호작용

### 존재 이유

장식이 그림에 그치지 않고 동물이 그 방에서 생활한다는 느낌을 준다. 가구를 바꾸는 이유를 몸짓으로 연결한다.

### 사용자 문제

침대·쿠션·탁자를 바꿔도 동물이 똑같이 움직이면 공간과 동물이 따로 논다.

### 함께/혼자 가치

함께: 친구가 놓은 가구가 내 동물의 작은 생활 장면이 된다. 혼자: 다른 배치를 시험하고 침대 휴식·쿠션 장난·탁자 관심을 바로 비교한다.

### 사용자 흐름

확정 방 진입 → 내 동물 선택 → 실제 놓인 침대/쿠션/탁자의 허용 상호작용 선택 → 가구 기준점으로 향하거나 제자리 자세 연결 → 침대 눈감기/쿠션 앞발 누르기/탁자 고개 들기 → 자연스러운 기본 자세 복귀. preview 가구는 실제 생활 근거로 저장하지 않는다. 반응 도중 친구가 회수하면 안전하게 중지한다.

### 즉각 피드백

세 가구군이 서로 다른 자세·시선·접촉으로 구별된다. 배율만 바꾸거나 state 문구 투영으로 완료하지 않는다. 바닥·발 기준점·깊이를 유지하고 동물/가구를 관통하거나 갑자기 순간이동하지 않는다.

### 재방문 이유

친구가 바꾼 가구에서 새로운 생활 장면을 발견한다. 배고픔 소모·일일 상호작용 횟수·학습 날짜를 보상 조건으로 붙이지 않는다.

### 단순 대안 비교

가구 설명문은 단순하지만 살아 있는 방의 차이가 약하다. 충돌 많은 자유 보행 AI보다 기존 고정 슬롯의 3개 안정된 장면을 먼저 완성한다. 동물 둘 공동 포즈는 #162 실험으로 별도다.

### 오프라인·실패·빈 상태

offline은 확정 캐시 기반 일시 연출만, DB상태 변경 불가. 호환 가구0이면 기본 C02반응. 권한 상실/회수/house change/background에 연출 취소. 가구 조회 실패를 없다고 확정하거나 비공개 가구 윤곽을 만들지 않는다.

### 소유권·RLS·개인정보

장면 감상은 읽기 권한 범위, 친구 동물의 영속 상태·배치·수량을 변경하지 않는다. 추억 가구는 viewer 검사를 통과한 데이터만 사용. 일반 가구로 추억 원문을 열지 않는다.

### 데이터·서버 책임

기존 카탈로그 category/interaction/anchor와 확정 placement 입력 → 로컬 reaction controller. 새 DB 기분/성장/보상 모델 없음. 지속 상태가 정말 필요할 때만 본인 action RPC 계약으로 별도 검증한다.

### 의존성

### 제거·축소 기준

의미 없는 자동 반복·눈의 과장·과한 이동이 산만하면 한 장면의 품질부터 줄여 개선한다. 반응으로 꾸미기의 가치가 늘지 않으면 확장 중단. 학습/가구 자산을 부작용으로 삭제하지 않는다.

## 실제 재미를 판단하는 방법

솔로 3명, 서로 아는 친구 3쌍(6명), 별도 4인 집 1개를 **첫 탐색 조사 제안**으로 둔다.
이는 통계적 유의성이나 모집 완료를 뜻하지 않는다. 개인정보 동의를 받고 가명으로만 기록한다.
각 그룹은 새 계정 진입, 동물 반응 구별, 방 미리보기 취소, 한 줄 공동 추억, 가구 원본 열기,
다음 방문 변화 찾기를 수행한다. 4인 그룹은 가구 교체 충돌과 후입주/퇴장 권한도 확인한다.

관찰값은 목표 이해 여부, 완료/중도 이탈, 걸린 시간, 잘못된 확정, 자발적 다시 만짐,
‘친구와 함께여서 달랐던 점’, 답변 압박, 다시 방문하고 싶은 이유다. 설명/도움 횟수도 적는다.
인터뷰 재미 평점은 실제 응답 수·질문·분포와 함께 보고한다. 4.8/5.0은 결과가 아니다.
개인 추억 원문·사진은 리서치 로그나 스크린샷에 복제하지 않는다.

탐색 조사에서 사용할 제품 판단선도 제안한다. 통계적 출시 보증이 아니며 실패하면
해당 기능의 축소 기준에 따라 바꾸고 재검증한다.
