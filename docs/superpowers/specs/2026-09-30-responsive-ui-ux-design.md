# 우리집 반응형 UI/UX 설계

작성일: 2026-09-30

## 목적

우리집을 모바일 우선으로 유지하면서 태블릿과 데스크톱에서 화면 폭을 낭비하지
않도록 한다. 방은 게임 장면으로 계속 중심에 두고, 목록·작성·설정 화면은 읽기와
조작이 편한 밀도로 확장한다. 이 작업은 화면 표현과 탐색 레이아웃만 다루며,
Supabase 데이터 계약·게임 규칙·Demo Mode 동작은 바꾸지 않는다.

## 현재 상태와 문제

`HouseGameShell`만 900px에서 하단 탭을 좌측 탐색 레일로 바꾼다. 그 외 화면은
각자 `maxWidth`, padding, 카드 폭을 정의해 다음 문제가 있다.

- 600~899px 태블릿 폭에 일관된 2열 목록과 여백 기준이 없다.
- 상세·작성·설정 화면의 제목, 뒤로가기, 스크롤 하단 안전 영역이 화면마다 다르다.
- 카드 그리드가 작은 폭에서 너무 좁아지거나 넓은 폭에서 과도하게 늘어날 수 있다.
- 방 무대와 꾸미기 tray가 가로·세로 화면에서 차지할 공간을 공통 계약으로 설명하지
  않는다.

## 반응형 구간

| 구간 | 너비 | 주요 목적 | 탐색 |
| --- | --- | --- | --- |
| compact | 0~599px | 한 손 조작과 세로 읽기 | 하단 탭, 스택 뒤로가기 |
| medium | 600~899px | 태블릿의 여백·목록 밀도 | 하단 탭 유지, 2열 목록 |
| wide | 900px 이상 | 방 무대와 보조 패널 병행 | 좌측 탐색 레일 |

구간은 React Native의 `useWindowDimensions`로 계산한다. 세로 높이는 방 무대의
최대 크기와 scroll 안전 영역에만 사용하고, 단말 기종 문자열로 분기하지 않는다.

## 공통 레이아웃 계약

새 `responsive` UI 유틸리티는 다음 값을 화면에 제공한다.

- `breakpoint`: `compact | medium | wide`
- `pageGutter`: compact 16, medium 24, wide 32
- `contentMaxWidth`: 정보 화면 760, 목록 화면 1120
- `gridColumns`: compact 1, medium 2, wide는 카드 최소 폭을 만족하는 3~4열
- `bottomSafeSpace`: 하단 탭이 있는 compact/medium 화면의 콘텐츠 끝 여백

`ResponsivePage`는 SafeArea, 수평 gutter, 최대 너비, 기본 scroll padding을
소유한다. 모든 페이지가 이것을 강제 사용할 필요는 없지만 상점, 보관함, 추억,
설정, 버릇, 개발 에셋, 집/인증 입력 화면은 이 계약으로 통일한다.

기존 모바일 뒤로가기 버튼은 compact/medium에서만 렌더하고 wide에서는 숨긴다.
기본 터치 영역은 44×44pt를 유지하며, 직접 링크로 history가 없을 때에는 화면별
fallback으로 돌아간다.

## 화면별 적용

### 홈과 꾸미기

`HouseGameShell`은 compact/medium에서 상단 집 정보·멤버 자리·하단 탭을 사용하고,
wide에서 좌측 레일과 넓은 방 무대를 사용한다. medium은 넓은 방을 보여 주되
데스크톱 레일을 강제하지 않는다. 방은 기준 좌표계를 유지하며, scene 크기는
viewport 높이와 탭/tray의 남은 공간 안에서 clamp한다.

꾸미기 tray는 compact에서 방 아래 bottom sheet처럼 보이고, medium에서는 더 넓은
가로 목록을 허용한다. wide에서는 방 무대 옆 보조 패널로 옮긴다. 가구 배치·소유권·
충돌 검사 API는 바꾸지 않는다.

### 상점과 보관함

상점 상품과 보관함은 compact 1열, medium 2열, wide 3~4열을 사용한다. 카드의
최소 폭은 156pt로 유지하고, 그보다 좁아질 때만 열 수를 줄인다. 카테고리 chip은
가로 스크롤을 유지해 줄바꿈으로 탭 순서가 흔들리지 않게 한다.

상점의 코인·필터·오프라인 상태는 제목 바로 아래에 두고, 구매 결과·부족 안내는
선택 상품 가까이에 표시한다. 보관함의 빈 상태는 상점으로 가는 CTA를 제공한다.

### 추억

추억 목록은 compact 1열 스크랩북, medium 2열, wide 2열의 읽기 폭 제한 앨범으로
전환한다. 상세와 작성은 어느 폭에서도 한 개의 읽기 열을 유지하며, 본문 줄 길이는
너무 길어지지 않게 760px을 넘지 않는다. 사진 업로드 실패와 권한 없음 빈 상태는
기존 글을 보존하는 현재 동작을 유지한다.

### 설정·집·인증·버릇

폼은 compact에서 전체 폭, medium/wide에서 520~720px의 중앙 열로 제한한다. 입력
화면은 키보드 회피를 유지하고, primary CTA가 키보드와 하단 safe area에 가려지지
않게 scroll 또는 padding을 사용한다. 집 생성/초대/입주 실패·만료·정원 초과 상태는
같은 페이지 폭과 뒤로가기 fallback 안에서 보인다.

## 접근성·모션

- 모든 조작 버튼은 최소 44×44pt, 접근성 이름, focus 가능한 순서를 가진다.
- 색만으로 선택 상태·소유권·오프라인 상태를 표현하지 않는다.
- 글자 크기 확대에서 card title, chip, CTA가 자르지지 않도록 `flexShrink`와 최소
  높이를 적용한다.
- reduced motion에서는 반복 방 애니메이션을 줄이고 layout 전환은 즉시 끝낸다.
- 하단 탭과 bottom sheet가 있는 화면은 마지막 카드 뒤에 충분한 scroll 여백을 둔다.

## 오류·오프라인 상태

반응형 변경은 로딩, 빈, 오류, offline read-only의 의미를 바꾸지 않는다. 각 상태는
현재 구간의 페이지 gutter와 읽기 폭을 사용하며, 확정 명령이 offline일 때 비활성인
이유를 화면에 남긴다. 데모 모드는 계속 명시적으로 표시되고, 실제 연결 오류를
데모 데이터로 전환하지 않는다.

## 테스트와 검증

- breakpoint 유틸리티: 390px, 768px, 1280px 입력에 따른 구간·gutter·grid 결과
- 공통 페이지: compact/medium/wide에서 하단 safe space와 desktop rail 여부
- 상점/추억/보관함: 각 구간의 열 수와 카드 최소 폭
- 방/꾸미기: 네 동물 터치 영역 비겹침과 tray가 방의 핵심 영역을 가리지 않는지
- 접근성: 뒤로가기·탭·구매·작성 CTA의 이름과 44pt 계약
- 실제 환경: 390×844, 768×1024, 1280×720 웹 브라우저와 iOS/Android Development
  Build에서 키보드·글자 확대·가로 회전·reduced motion 확인

웹 수동 검증과 iOS/Android 실기기 검증은 별도로 기록하며, 하나를 다른 하나의
검증 결과로 표현하지 않는다.
